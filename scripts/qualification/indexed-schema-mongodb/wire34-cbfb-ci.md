# Explicit Wire34 indexed/native qualification

This source-only successor selects the merged Wire package `1e7547ff` with the
root and independent MongoDB SDK both pinned to `cbfb2669`. Wire retains its own
`58d68c5` SDK installation. The existing Wire69 modules and descriptors remain
unchanged and continue to reject this graph.

The finite assembly is `indexed-schema-all-cbfb-root-native-wire34-engineering-v1`.
The native fixture is `indexed-schema-mongodb-wire34-cbfb-linux-gha-v1`. Their
admission checks the exact current indexed source/emissions and the full Wire34
source inventory, all four MongoDB/BSON installations, and actual Wire Node/Rust
source and preparation receipts. The native import graph has its own bounded
current route capture; it never rewrites the historical manifest.

The new runner/controller/contract differ from the frozen all-CBFB counterparts
only in explicit imports, profile identity and runner path. All twelve native
cases, assertions, comparison semantics, budgets, resource limits and cleanup
operations remain unchanged. The original finite, packed-consumer and teardown
controls still run; the teardown controls select the actual new source files.
Pure equivalence and old-profile refusal controls cover this routing boundary.
Both CLI admission and the native entrypoint require a clean complete Git census
bound to the actual GitHub run identity before any database effects. New receipts
use a separately named namespace below ignored `out/`, so output files do not
masquerade as unreviewed source or collide with historical evidence.

Run the current jobs with ordinary committed-lock installs and the existing
Bun 1.4.4 / TypeScript 7.0.2 whole-project checks. Metadata capture is an authoring
operation that must be reviewed; CI never regenerates expected source hashes.
Windows controls inspect source and installed bytes only. Native MongoDB and
Linux process lifecycle results are pending until the new CI run completes.

This does not qualify Atomic SQL, managed HTTP, full Wire replay/current-testnet
sync, production offers, performance or release readiness. The separate physical
Wire121/122 assembly remains on `29bf6d07` / Wire `e691f447`.

This slice migrates only the active finite and indexed-native jobs. The parent
Build & Test and managed Atomic workflows still select Wire69 source profiles;
they require a separate explicit integration before the parent release stack can
merge. Passing these four jobs alone does not establish parent merge readiness.
