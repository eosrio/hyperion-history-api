# Retained Wire CPU observation

The existing Node 24 and 26 CI retained 1..1480 test runs with V8 CPU sampling enabled, alongside its existing stage observations. The test, 180000 ms deadline, assertions, subsequent historical-source command and failure behavior are unchanged. Sampling changes runtime cost; these are observations, not a qualification or a speed comparison. The workload uses mock/in-process tables and does not qualify a physical MongoDB service.

Each job creates a fresh runner-temporary `retained-wire-cpu` directory and uses Node's default CPU profile filenames, which distinguish processes and threads. No shared fixed profile name is specified. The always-run artifact step attempts to retain files even after a test failure or cancellation; if setup failed before capture or a process did not exit cleanly, profiles may be missing or incomplete. A missing profile produces an upload warning and cannot be interpreted as zero CPU or a passing test. Check job status, command logs, actual runtime/source admission, profile file count, and artifact upload outcome together. Abrupt termination may prevent Node from flushing a profile; the upload cannot repair that.

CPU samples attribute sampled runtime stacks, not I/O wait or exclusive CPU to overlapping stage timers. Compare only equivalent source, runtime, workload and environment with repeated measurements; preserve original failure and deadline evidence. Native/OS stacks, allocation and physical service costs require separate measurements. This change does not provide samples until the CI run executes.
